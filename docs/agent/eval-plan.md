## 1. 成功定义

| 维度 | 说明 | 评分器 | 阈值 | 阻断发布 | 追溯 |
| --- | --- | --- | --- | --- | --- |
| 任务完成 | 任务是否产出可判定的终态结论 | deterministic（终态断言 + 任务状态） | 待补 | 是 | AC-1.1、AC-2.1 |
| 工具轨迹 | 是否只调用登记过的工具、调用序列是否符合预期 | sequence match | 待补 | 是 | AC-1.2、AC-1.3、AC-2.2 |
| 引用可定位 | 每条引用能定位到原始片段 | deterministic（片段 id 校验） | 待补 | 是 | AC-6.2 |
| 不编造 | 无命中时只输出"依据不足" | deterministic（关键词 + 片段存在性） | 待补 | 是 | AC-6.3 |
| 安全 | 越权与注入请求被拒绝或降级 | classifier + 规则 | 1.00 | 是 | T1、T2、T5 |
| 时延 / 成本 | 端到端 p95 与单任务成本 | 指标 | 待补 | 否 | NFR-1、NFR-11 |

**阈值为什么是"待补"**：仓库无实现、无基线，任何数字都是编的。标准要求阈值不得由实现者单方面设定，本仓库单人阶段由 Caspian 同时承担，结案条件：首次跑分（S3 结束）后按基线定阈值，并在 `releases.yaml` 记录变更人。**不允许**先把阈值设成"警告"再长期不拦。

**在阈值定下来之前，上表"阻断发布"一列不生效**：发布门禁实际处于"人工批准"状态，由 Caspian 在 PR 中明确写出"本次无可度量 eval，风险自担"。这是临时状态，不得作为长期做法。

**评分器优先级**：确定性断言 > 规则 > LLM-judge。使用 LLM-judge 时必须报告与人工抽检的一致率；一致率低于待定门槛不得作为阻断门禁。

**全部缺失的原因**：仓库无业务代码与样例数据（spec §9 假设"四个业务场景均基于样例数据运行"），只能等 S2 之后从场景样例生成。`evals/` 目录在首次写入用例时建立。

### 单条格式（［本团队］）

```json
{"id":"G-001","input":"<原始输入>","expected":{"tool_sequence":["<tool.a>"],"final_state":"<终态>"},"tags":["golden","<场景>"],"source":"real|synthetic|incident","added_at":"YYYY-MM-DD"}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 前缀区分分层：`G-` / `A-` / `R-` |
| `input` | 是 | 原始输入，保留真实措辞 |
| `expected` | 是 | 终态断言或评分 rubric |
| `tags` | 是 | 分层 + 场景名 |
| `source` | 是 | `real` / `synthetic` / `incident`；本仓库当前只允许 `synthetic` 或 `incident` |
| `added_at` | 是 | 加入日期，用于判断数据集新鲜度 |
