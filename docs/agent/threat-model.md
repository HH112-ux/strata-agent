## 2. 资产

| 资产 | 类型 | 敏感性 | 被破坏的后果 |
| --- | --- | --- | --- |
| 模型服务 API Key（火山方舟） | 凭证 | 机密 | 盗刷配额、费用损失、数据外发 |
| 工具执行能力（ToolRegistry） | 能力 | 高 | 越权动作、执行未登记能力 |
| MCP 网关审计记录 | 数据 | 内部 | 无法定责、取证断链 |
| 跨会话记忆（Redis，会话记忆） | 数据 | 个人 | 记忆污染、跨会话串味 |
| 知识库向量与片段（PostgreSQL + pgvector） | 数据 | 内部/个人 | 检索内容被投毒、PII 扩散 |
| 评测样本与基线（`evals/`） | 数据 | 内部 | 基线被篡改，回归门禁失效 |
| 仓库本身 | 供应链 | 高 | 密钥入库、恶意依赖 |
| 结论的可信度（引用可核查） | 信任 | 高 | 伪造出处，用户据错结论行动 |

## 3. 信任边界

| 输入源 | 内容由谁控制 | 是否可信 | 进入路径 | 备注 |
| --- | --- | --- | --- | --- |
| HTTP API / 命令行任务输入 | 调用方 | 部分 | 直接 | 直接注入入口 |
| 上传的合同与文档（合同预审场景） | 外部内容提供者 | 否 | 检索 / 上下文 | **主要间接注入入口** |
| RAG 知识片段（pgvector） | 内部导入，可被污染 | 视来源 | 检索 | 记忆与上下文投毒（ASI06） |
| MCP server 返回值 | 第三方 server | 否 | tool | 接入后可发起 SSRF 式诱导 |
| 模型服务返回 | 厂商 | 部分 | model_call | 上游被替换即供应链风险 |
| Redis 会话记忆 | 历史会话写入 | 否 | 检索 | 可被单次会话污染 |
| 本地宿主机环境变量 | 开发者 | 是 | 启动配置 | Key 存放位置，不得落日志 |
| 仓库依赖（Spring AI / LangChain4j / 镜像） | 上游维护者 | 部分 | 构建 | 版本锁定是唯一约束（constitution §3） |

**规则**：每个箭头都必须标"内容由谁控制"；标不出来的说明数据流没画清。上表全部已标。

## 6. 三元组判定

| 维度 | 是否具备 | 证据 |
| --- | --- | --- |
| 私有数据 | 是（设计上） | 跨会话记忆、知识库片段、任务与调用记录；当前仅样例数据 |
| 不可信内容 | 是 | 合同与文档正文、MCP server 返回、RAG 片段 |
| 外部通信 | 是 | 模型服务 API、MCP 工具可调用外部系统 |

**结论（三项全为"是"）**：必须断开其一或强制人工确认。本仓库**要求**采取的控制（落地状态见 T3、T6）：

1. **断开"外部通信"的默认通路**：对外写操作必须先在 D1 登记；未登记一律拒绝。
2. **第三方 MCP server 默认不授予写权限**，只能接入已登记的只读 scope（登记流程待补）。
3. **工作流可选人工介入节点**，作为对外动作的兜底；默认是否强制，待补：需在 D1 的 `requires_approval` 落地时确定。

**残余风险接受人**：Caspian（单人阶段），结案条件：引入第二位评审人后重签。
